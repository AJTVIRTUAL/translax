01Qui je suis / ce qu'on construit

Je développe TRANSLAX, un logiciel de traduction de documents 100% local (aucune donnée envoyée en ligne), basé sur le modèle NLLB-200 de Meta AI. Le projet vit dans C:\DEV\TRANSLAX\. Deux volets en parallèle :

Pipeline de traduction

txtTraduction/pyTraduction/ — scripts Python pour traduire mes propres livres/documents EN → FR.

Application de bureau

PROJECTS/TRANSLAX/ — appli PySide6 avec interface graphique complète, v1.10.0 actuellement.

02Règles établies — à respecter dans la suite

  • Ne jamais traduire un livre/document en le générant toi-même. Question de droits d'auteur — toujours passer par le moteur mécanique local NLLB-200 qui tourne sur ma machine.
  • Réglages de traduction sûrs, ne pas changer sans vérifier : séquentiel (batch_size=1), num_beams=4, no_repeat_ngram_size=3. Le batching (>1) et le décodage glouton (num_beams=1) ont provoqué des boucles de répétition — bug réel, déjà constaté.
  • Écriture du fichier de sortie incrémentale obligatoire. Flush après chaque segment traduit — un bug passé écrivait tout seulement à la fin, laissant croire que le programme était bloqué pendant des heures.
  • CTranslate2 : deux statuts différents à ne pas confondre. La première intégration montrait des régressions de qualité mesurées. Une intégration plus propre existe maintenant dans l'appli sous le nom « 600M — Turbo », ~13× plus rapide, sortie quasi identique. Les deux coexistent, l'utilisateur choisit.
  • Machine de référence : HP Pavilion, AMD Ryzen 7 4700U, 8 cœurs, pas de GPU dédié. Toute mesure "sur cette machine" dans le code/les docs y fait référence.

03Historique de ce qui a déjà été fait

  1. Traduction de The Laws of the Universe and Life

    PDF → Les lois de l'univers et de la vie.md. Scripts créés : prepare_source.py, translate_document.py, puis cleanup_headings.py pour le nettoyage.

  2. Exploration de la vitesse

    Batching, décodage glouton, CTranslate2 — voir les règles établies ci-dessus pour les conclusions retenues.

  3. Traduction de Bloodlines of the Illuminati, volumes 1 et 2

    Fichiers .txt sans aucune ligne vide → nouveau script prepare_book_source.py pour reconstruire des paragraphes par regroupement de phrases. Résultats dans PROJECTS/TRANSLAX_MANUAL/Books_Traduits/.

  4. Prompt réutilisable pour lancer une traduction

    PROJECTS/TRANSLAX_MANUAL/PROMPT_TRADUCTION.md — une commande, deux chemins à changer.

  5. Conception puis construction de l'application de bureau

    Spec initiale : PROJECTS/TraducteurNLLB-Desktop/SPEC.md. Application réelle dans PROJECTS/TRANSLAX/. 6 profils de modèle disponibles : 600M, 1.3B, 3.3B, 600M Turbo, OPUS-MT (licence CC-BY 4.0), MADLAD-400 (licence Apache 2.0). Un TRANSLAX.exe packagé existe dans dist/.

  6. Logo « TX »

    Prompt dans LOGO_PROMPT.md, logo obtenu, visible dans captures/icone_apercu.png.

  7. Guide de test animé pour un testeur externe

    Acer Nitro 16S AI (Ryzen AI 9, RTX, 32 Go RAM) comparé à ma machine de référence. Fichier : PROJECTS/TRANSLAX/translaxguide.html. Contenu : présentation, galerie de captures, installation, alerte CUDA/PyTorch critique, réglages du test, choix du livre (300 pages minimum), checklist de retour.

  8. Exploration OCR/vision locale

    Objectif : remplacer la dépendance à l'API Anthropic payante de « Traduire X » (core/vision_ocr.py) pour rendre TRANSLAX vraiment 100% local. PaddleOCR installé et testé avec succès (licence Apache 2.0, commercialisable) — script ocr_prototype.py. Bug rencontré et corrigé : PaddlePaddle 3.3.1 plante à l'inférence CPU avec oneDNN activé par défaut → fix enable_mkldnn=False. Comparatif complet (licences, VLM candidats : Qwen2.5-VL, GOT-OCR2.0, InternVL, MiniCPM-V) dans OCR_VLM_COMPARATIF.md. Pas encore intégré dans l'appli.
